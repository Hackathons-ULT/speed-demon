# A: Ingest

The timestamp grammar fixes the UTC hour in the first 13 bytes. Every seed has the specification's same 72-hour UTC span, so parsing its month/day/hour yields a direct bucket index instead of hashing a calendar string for every request. Endpoint strings are interned as views into a read-only input mapping on Linux, and each endpoint owns 72 groups. No endpoint catalogue or input answers are embedded. Windows uses a private input buffer for development checks.

Four workers scan the same immutable mapping. An endpoint's hash assigns it to exactly one worker; other workers skip that record after finding its delimiters. Thus every request contributes once, each group has a single writer, and no latency arrays need to be copied or merged. A worker's 4,096-slot linear-probing endpoint table stays below half full under the specified maximum of 1,842 endpoints. Exact byte comparison resolves hash collisions. Empty views are safe sentinels because valid endpoints begin with `/`.

Unsigned 32-bit latencies are retained exactly. Groups of at most 64 values are sorted; larger groups use progressive `nth_element` selection at the three integer nearest ranks `(p*n+99)/100-1`. Each later selection starts after the previous selected rank, so earlier selected values stay fixed and global rank is preserved, including duplicate values and coincident ranks. Each worker finishes its own groups before joining. Statuses beginning with 5 increment errors; error ppm uses a 64-bit product and integer division. Output numbers use locale-independent `to_chars` into a bounded stack buffer, with one buffered write per line.

Endpoint keys sort bytewise once, then hours iterate in chronological bucket order. Original timestamp prefixes supply output hour bytes, including the month boundary. Input order is irrelevant, duplicate lines count separately, and UINT32_MAX latency remains exact. Empty input produces an empty file.

Auxiliary storage is O(requests + endpoints * 72), plus four bounded lookup tables and thread stacks. Four scans trade additional CPU work for parallel latency; only the owner parses numeric fields and stores latencies. Large-group rank selection is expected linear, small-group sorting is bounded by 64 values, and endpoint-key sorting happens once. All workers join before output reads their results. The mapping is read-only and no derived state persists across runs. C++ standard library and POSIX mapping/thread calls add no runtime package dependency. Build with `-pthread`.
