# A: Ingest

The timestamp grammar fixes the UTC hour in the first 13 bytes. Every seed has the specification's same 72-hour UTC span, so parsing its month/day/hour yields a direct bucket index instead of hashing a calendar string for every request. Endpoint strings are interned as views into a read-only input mapping on Linux, and each endpoint owns 72 groups. No endpoint catalogue or input answers are embedded. Windows uses a private input buffer for development checks.

Six workers parse disjoint contiguous input ranges. Each internal boundary advances to the next LF, which is a record boundary under the log grammar; ranges remain exhaustive and non-overlapping regardless of timestamp disorder. A 4,096-slot concurrent endpoint table stays below half full under the specified maximum of 1,842 endpoints. Each published key is immutable: release/acquire publication makes its exact byte view visible before another worker reads it. Exact comparison and linear probing resolve collisions; keys are never removed while workers run.

The first pass counts each `(endpoint, hour)` group and errors, then skips the latency bytes. A prefix sum gives every group one exact region in a flat latency array. Counters reset and become atomic cursors. The second pass rereads the same immutable input, parses each latency, and fetches a cursor to obtain a unique destination within its group's region. After all scatter workers join, group counts are restored and the array contains the same complete latency multiset. This trades a second endpoint/time parse for eliminating the temporary packed-record buffer.

Unsigned 32-bit latencies are retained exactly. Workers select disjoint groups: groups of at most 64 values are sorted, while larger groups use progressive `nth_element` selection at integer nearest ranks `(p*n+99)/100-1`. Each later selection starts after the previous rank, preserving earlier selected values and global ranks, including duplicates. Statuses beginning with 5 increment errors; error ppm uses 64-bit multiplication and integer division.

Endpoint keys sort bytewise once. Six formatters each own a consecutive range of hours and a private output string. They emit sorted endpoint lines using locale-independent `to_chars` and a bounded stack buffer. After joining, the main thread writes those strings in hour-range order. Original timestamp prefixes supply output hour bytes, including the month boundary; one atomic claim selects a single prefix writer per hour, and no prefix is read until the counting workers join. Input order is irrelevant, duplicate lines count separately, and UINT32_MAX latency remains exact. Empty input produces an empty file.

All phase transitions join every worker. The mapping and published keys are immutable; counting/scatter cursors are atomic; latency destinations, rank groups and formatted strings each have one writer. Auxiliary storage is one four-byte latency per request, fixed metadata for `4096*72` groups, and rendered output. Both passes read only the same mapped file. Large-group selection is expected linear, small-group sorting is bounded by 64 values, and endpoint sorting happens once. No derived state persists across runs. C++ standard library and POSIX mapping/thread calls add no runtime package dependency. Build with `-pthread`.

With another 24 hours, compare the packed-record alternative and tune worker count and endpoint hashing on the genuine Board. Extra source and peak memory are priced; retain a candidate only when its measured coefficient improves.

After rank workers join, the flat latency array and its offsets are no longer needed: the three selected values have been copied into each group. They are released before formatting starts. After formatter workers join, their private strings own all output bytes, so group storage is released before file writes. Each string is released after its synchronous write. These phase boundaries keep dead arrays, rendered output and charged output-file pages from accumulating at the same peak; the algorithm and byte order are unchanged.

Distribution assumptions: the specified 72-hour span and catalogue bound determine storage sizes. Zipf popularity, day/night rates and latency tails guide experiments only; every input record and full uint32 latency is processed exactly, without a bound on ordering disorder. The deterministic CI fixture shuffles non-Zipf groups and checks all 500 statuses, rank boundaries, duplicates, month rollover and maximum-length keys against an independent oracle.
